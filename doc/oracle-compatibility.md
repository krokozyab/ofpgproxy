# Oracle-wire client compatibility

This page is generated by hand from `ofpg`'s `internal/orawire/compatibility.go`
registry — the single authoritative, machine-readable source of what the
Oracle-wire frontend actually supports. Run `ofpgproxy doctor --profiles` for
the live version of this table straight from the binary you're running; if
the two ever disagree, the binary is right and this page is stale.

Every grade below is evidence-based, not aspirational:

| Grade | Meaning |
|---|---|
| **verified** | A live protocol capture against a real client, backed by an automated regression test. |
| **experimental** | Works in practice (a real capture or live session exists), but no automated test guards it — a regression here would not be caught by `go test`. |
| **unsupported** | Deliberately, architecturally absent (e.g. no code path exists at all). |
| **unknown** | Genuinely never independently checked either way — not the same as unsupported. |

A profile or feature graded **verified** always cites the specific test(s)
backing it. "The code path exists" is never, by itself, treated as evidence.

## Generic thin client (`thin-generic`)

Any thin (pure-Java/pure-Python) client the proxy can't specifically identify
as the ojdbc family below — chiefly **python-oracledb in thin mode**. Overall:
**verified**. Protocol versions 300–319.

This profile is a catch-all for "thin, but not identified as the ojdbc
family" — no CID PROGRAM or TTIPRO driver-name string for python-oracledb is
recognized anywhere in this codebase, so it's classified by elimination. Every
feature below is verified specifically against a real **python-oracledb 4.0.1**
thin-mode client (thin is the library's own default — no Instant Client
involved) driven end to end against a live server instance; `auth.go`/
`execute.go` have no per-driver branching for thin at all, so the same code
serves any other thin client, but only python-oracledb has an actual capture
backing it.

| Feature | Grade | Notes |
|---|---|---|
| O5LOGON auth | **verified** | `auth_test.go` — real AUTH_PHASE_ONE/TWO captures parsed, `deriveComboKey`/`checkPassword` run against a real client's session-key shape. |
| EXECUTE/FETCH | **verified** | `fetch_test.go` — a real EXECUTE + follow-up FETCH round-trip, rebuilt responses match the capture byte-for-byte. |
| Bind variables | **verified** | `bind_test.go` (string substitution) + `fetch_test.go` (the real wire-level bind decoder, a live `id=2` NUMBER bind). |
| NULL values | **verified** | `fetch_test.go` — a real NULL cell (decoded by the client as `None`), byte-exact against the capture. |
| Multi-row/multi-column | **verified** | `fetch_test.go` — 3 columns × 3 rows, split 2+1 across EXECUTE/FETCH (python-oracledb's default `prefetchrows=2`). Verified only up to this shape. |
| Wide results (>255 cols) | **verified** | `wide_test.go` — a real 300-column, 1-row capture. The thin dialect has no OCI/dblink-style >255-column special case at all (DESCRIBE_INFO/ROW_DATA encode columns linearly over ordinary SDU-based Data-packet fragmentation), so this threshold doesn't apply to it. Verified for a single row only. |

## Classic OCI — `sqlplus` on a pre-23ai / non-fast-auth Instant Client (`classic-oci-sqlplus`)

Overall: **verified**, but narrowly scoped. Protocol versions 315–319.

**Verified scope is single-column, single-row NUMBER/VARCHAR2/DATE only** —
wider or other-typed shapes need their own live captures before being
trusted.

| Feature | Grade | Notes |
|---|---|---|
| EXECUTE/FETCH | **verified** | `oci_execute_test.go:TestParseOCIExecute` (2 live captures), `oci_auth_test.go`. |
| NUMBER | **verified** | 7 live sqlplus captures; 2-row FETCH verified. |
| VARCHAR2 | **verified** | 7 live sqlplus captures; single-row only. |
| DATE | **verified** | 7 live sqlplus captures; single-row only. |
| Bind variables | unknown | No capture or test exists with an actual bind variable over classic OCI. |
| NULL values | unknown | Only a retired function's design note, not a live capture of an actual NULL cell. |
| Multi-row/multi-column | unknown | Scoped to single-column responses. |
| Wide results (>255 cols) | **unsupported** | `oci_describe.go` scopes itself to single-column/single-row only. |
| ANO encryption / TCPS | **unsupported** | See [below](#ano--native-encryption--tcps). |

## Modern OCI fast-auth — 23ai/26ai-era direct `sqlplus` (`fast-auth-oci-sqlplus`)

Overall: **verified**, but narrowly scoped. Protocol versions 319–320.

**DATE is not implemented at all for this dialect** — this is distinct from
ANO, which is *deliberately* unsupported; DATE is simply absent from the
type map. Verified scope is single-column responses only, beyond a single
2-NUMBER-column/3-row capture.

| Feature | Grade | Notes |
|---|---|---|
| EXECUTE/FETCH | **verified** | `oci_execute_test.go:TestParseOCIExecuteFastAuth`. |
| VARCHAR2, CHAR, NUMBER, TIMESTAMP, BINARY_FLOAT, BINARY_DOUBLE, RAW, INTERVAL YEAR TO MONTH, INTERVAL DAY TO SECOND | **verified** | Each backed by its own live capture in `oci_describe_fastauth_test.go`. |
| CLOB (read) | **verified** | `oci_lob_fastauth_test.go`. |
| DATE | unknown | Completely absent from the type map — not implemented, not deliberately excluded. |
| Bind variables | **verified** (narrow) | `oci_execute_test.go:TestParseOCIExecuteFastAuthBind(Null)` — **NUMBER only**; no VARCHAR2/DATE/other-type fast-auth bind capture exists. |
| NULL values | experimental | `TestBuildOCISingleRowResponseFastAuthRejectsBadRawValue` proves NULL rejection for 7 of the 9 fixed-width types is deliberate — those 7 genuinely cannot return NULL by design. VARCHAR2/NUMBER can plausibly carry NULL. |
| Multi-row/multi-column | **verified** (narrow) | Only a 2-NUMBER-column, 3-row shape is captured/tested. |
| Wide results (>255 cols) | **unsupported** | Both existing captures are single-column; treated as single-column-only until a real multi-column capture exists. |
| ANO encryption / TCPS | **unsupported** | See [below](#ano--native-encryption--tcps). |

## Oracle `dblink` shadow session (`oracle-dblink-shadow`)

A real Oracle database reaching the proxy through its own outbound `dblink`.
Overall: **verified**. Protocol version 320 (confirmed byte-for-byte against
2 independent live Oracle-to-Oracle dblink captures — the same protocol
version fast-auth uses, **not** 319).

| Feature | Grade | Notes |
|---|---|---|
| EXECUTE round1 (describe-only) / round2 (describe+data) | **verified** | `oci_execute_test.go:TestParseOCIExecuteDblink`, `oci_dblink_describe_test.go`, `oci_dblink_multi_test.go` — 3+ live captures, 1-4 columns. |
| A second, distinct query on the same session | **verified** | `oci_dblink_state_test.go` — a real regression: a 2nd distinct query was once mis-answered as a continuation of the 1st. |
| Multi-row/multi-column | **verified** (narrow) | Real captures at 1/2/3/4 columns only. |
| Wide results (>255 cols) | **verified** | Real 288-column, all-NUMBER capture (`PO_HEADERS_ALL`); unverified for an all-DATE 3+-column wide set. |
| Bind variables | unknown | The only dblink EXECUTE capture/test has zero bind variables. |
| NULL values | unknown | The existing fix covers round-1 nullable-column describe metadata, not an actual NULL cell value in a FETCH/EXECUTE row. |
| Session-sync 0x44 per-column index description | experimental | Live-verified only against one real 288-column, all-NUMBER, **no-index** capture. No signal exists anywhere in this codebase for whether a projected column is actually indexed — sending the wrong response shape has been observed to hang a real client indefinitely. |
| ANO encryption / TCPS | **unsupported** | See [below](#ano--native-encryption--tcps). |

## Unrecognized client (`unknown-client`)

A reserved fallback. Today's boolean signals (thick/dblink/fast-auth) are
exhaustive, so the proxy never actually classifies a real connection this
way — kept for registry completeness and as a defensive default. **An
unrecognized/unverified profile is always a warning, never a rejection** —
classification alone never blocks a connection.

## ANO / native encryption / TCPS

Every OCI/thick profile above (classic, fast-auth, dblink) shares the same
answer: **unsupported**. `ano.go`'s `handleANO` only ever sends a fixed "no
native security" reply — there is no crypto-negotiation branch anywhere in
the Oracle-wire package. A client that insists on native encryption/TCPS
(`SQLNET.ENCRYPTION_CLIENT=REQUIRED`, TCPS in `sqlnet.ora`) fails at the ANO
step. Terminate TLS in front of the proxy instead if transport encryption is
required.

## Checking your own installation

`ofpgproxy doctor --profiles` prints this same registry from the binary
you're actually running, with zero Fusion calls. `ofpgproxy doctor` (see
[troubleshooting](troubleshooting.md)) additionally reports which profile a
real connection resolved to, via `compat_profile`/`compat_support` in
connection logs and diagnostic bundles.
